# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A snippet-only editor extension for authoring [LiaScript](https://LiaScript.github.io) courses (extended Markdown). It ships to VSCode and Atom from one source, and the same source also feeds the Monaco editor and CodiLIA. There is no application code and no test suite.

## Source of truth and generated outputs

- `snippets/*.cson` is the canonical source. Atom loads these files directly. Every file uses the scope `'.source.gfm, .text.md'`, and each entry is keyed by a human-readable label with these fields:
  - `prefix`: the trigger. Conventions: `lia-…` for syntax, `voice-…` for narrator voices, `hili-…` for highlight languages.
  - `body`: TextMate snippet syntax (`${1:placeholder}`, `$2`).
  - `description`: `"""…"""` help text (short explanation, then an indented `Example:`).
  - `descriptionMoreURL` and `leftLabelHTML`: required on every entry (docs link, emoji icon).
  - Optional per-target overrides: `body_vscode` replaces `body` in the VSCode output. Put choices (`${1|a,b|}`) only there, because Atom has no choices. `body2` replaces `body` in the Monaco output.
- Generated by `cson2json2.py` (see below), all committed:
  - `vscode/markdown.code-snippets`: VSCode, the only file in the `.vsix`.
  - `monaco.json`: plain text, snippet syntax stripped by `remove_pattern`.
  - `default.json`: CodiLIA format.
  - Snippet keys become VSCode keys, so keys must be unique across all CSON files.

## Writing snippet bodies (escaping pitfalls)

- CSON `"""` strings are CoffeeScript strings: `\\` → `\`, and `#{…}` interpolates, so avoid writing `#{`.
- In a body, `$` followed by a digit or a letter is a tab stop or variable in VSCode and Atom. Write `\\$` in CSON for a literal `$`, or keep math (`$…$`) out of bodies.
- Inside a placeholder, escape `}` as `\\}` in CSON. Never escape `{`: VSCode keeps the backslash of `\{`.

## Generate

Requires `pip install cson==0.8`, e.g. in a venv.

```
python3 cson2json2.py --all                    # -> default.json
python3 cson2json2.py --format vscode --all    # -> vscode.json, then:
cp vscode.json vscode/markdown.code-snippets
python3 cson2json2.py --format monaco --all    # -> monaco.json
```

When adding a new `.cson` file, add it to the hard-coded `--all` list in `cson2json2.py`. `cson2json.py` is the older stdout-only CodiLIA converter.

## Packaging / release

- VSCode: bump `version` in `package.json` (and `package-lock.json`), then run `npm run pack` (`npm i && vsce package`, needs `vsce`) to get `liascript-snippets-<version>.vsix`. Release commits are titled `Prepare vX.Y.Z release`.
- `.vscodeignore` keeps the CSON sources, the generators and the other outputs out of the VSCode package.
- Atom installs straight from the GitHub repo or `apm`, using `snippets/` as is.

## Verifying changes

There are no automated tests. To check a change:

- Load every CSON file and check for duplicate prefixes and keys, missing fields, and unescaped `$` in bodies.
- Regenerate all outputs and validate them with `python3 -m json.tool`.
- Render expanded bodies in a scratch course with the LiaScript devserver.
